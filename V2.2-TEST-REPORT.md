## Scope

The host runtime now controls a transaction around mutating Agent work:

```text
Snapshot → Agent/DAG mutation → Diff → Verification Gate → Commit / Rollback
```

The Agent does not receive a transaction commit/rollback tool.

## Snapshot boundary

Default transaction limits:

```text
Max files: 20,000
Max snapshot bytes: 250 MB
Retention: 20 transaction snapshots per Workspace
```

Excluded from snapshots:

```text
.git
.abdulkarem
node_modules
dist
build
.next
coverage
.venv
venv
__pycache__
```

If snapshot creation exceeds limits, the mutating Agent run is blocked before mutation begins.

## Verification policy

For coding work, v2.2 runs the project check gate after Agent execution. Tests can be included through `transactionIncludeTests`.

If the gate fails and `transactionAutoRollback` is enabled, the Workspace is restored to the pre-run snapshot.

For a failed/cancelled DAG, the transaction is not treated as verified even if some earlier mutation node completed.
