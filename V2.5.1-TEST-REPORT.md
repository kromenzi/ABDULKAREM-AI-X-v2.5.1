# ABDULKAREM AI X v2.5.1 — Windows Stability & UI Overlap Test Report

## Trigger

This hotfix follows a real Windows/Codex evaluation plus user screenshots showing right-panel tab collisions, capability icon-grid overlap, Deep Research panel crowding, and chat/composer visual intrusion. The same release also addresses the earlier CRLF, dependency drift, browser fallback and Electron sandbox findings.

## Fixes implemented

- CRLF/LF-normalized regression helpers.
- Exact direct dependency pins; TypeScript pinned to `5.9.2`.
- Windows lockfile bootstrap followed by `npm ci`.
- `sandbox:true`, `contextIsolation:true`, `nodeIntegration:false` for the main Electron window.
- Browser/Vite fallback screen when `window.abdx` is unavailable.
- Monaco lazy loading.
- Bounded three-column desktop layout with `minmax(0,1fr)` center and clamped right rail.
- Right-panel content isolated from capability controls.
- Capability area converted from a multi-row grid into a fixed 72px horizontal scrolling rail.
- Right tabs converted to non-wrapping horizontal scrolling tabs.
- Context/router/model text clipping and ellipsis.
- Responsive 1280px compact rail and <1050px right-panel collapse.
- New `ui-layout-stability.test.js` wired into `npm run check` and Windows checks.

## UI overlap invariants

The regression test asserts:

1. Desktop layout reserves a bounded right rail and clips cross-column overflow.
2. Right-panel rows are `42px / minmax(0,1fr) / 72px`.
3. Right tabs scroll horizontally and never wrap over each other.
4. Right content cannot paint into the capability rail.
5. Capability controls use fixed 78px cells in a horizontal scrolling rail.
6. The context strip clips long model/router labels.
7. At 1280px the rail compacts; under 1050px the right panel hides instead of covering chat.
